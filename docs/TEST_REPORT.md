# Отчёт о проверке MVP

Дата проверки: 2 сентября 2026 г.

Проверка выполнялась на копии рабочей базы, поэтому тестовые клиенты и заказы не попали в поставляемый `data/shop.db`.

## Исходный импорт

- товаров: 413;
- HOCO: 298;
- Borofone: 115;
- уникальных файлов изображений: 707;
- привязок изображений к карточкам: 826;
- дублирующихся штрихкодов: 0;
- предупреждений импорта: 0.

## Серверные сценарии

Успешно проверены:

- главная страница, фильтры, сортировка и пагинация;
- карточка товара и выдача изображений;
- API актуализации корзины;
- оформление заказа из нескольких товаров;
- пересчёт суммы на сервере по актуальным ценам;
- отказ от частичного заказа, если один из товаров стал недоступен;
- вход и выход из админки;
- просмотр заказов и смена статуса;
- просмотр и редактирование товаров;
- CSV-выгрузка с защитой текстовых значений от формул Excel;
- повторный импорт того же XLSX: 0 новых, 0 обновлённых, 413 без изменений;
- отсутствие дублей после повторного импорта;
- health-check `/healthz`.

## Браузерный сценарий

В Chromium проверена DOM-логика корзины:

- добавление товара;
- открытие боковой корзины;
- увеличение количества;
- удаление позиции;
- обновление счётчика.

JavaScript-файлы дополнительно прошли синтаксическую проверку `node --check`, Python-файлы — `compileall`, все Jinja-шаблоны — компиляцию окружением Jinja2.

## Что не проверялось в этой среде

Docker daemon в среде сборки отсутствовал, поэтому образ не собирался локально. Само ASGI-приложение было запущено напрямую через Uvicorn, а Dockerfile использует тот же модуль `app:app` и тот же Uvicorn.

Онлайн-эквайринг не подключён: для него нужны договор и секретные ключи выбранного платёжного провайдера.

## Обновление: количество на карточках и персональные данные

Дополнительно проверены изменения текущей сборки:

- на карточках каталога и странице товара присутствуют элементы `− / число / +`;
- количество можно вводить вручную в диапазоне 0–999; значение 0 удаляет товар из корзины;
- значение на карточке и значение в боковой корзине используют одно хранилище и пересчитывают общий счётчик/сумму;
- сервер не создаёт заказ без `personal_data_consent`;
- при корректном согласии в заказ сохраняются факт согласия, версия политики и UTC-время;
- старая SQLite-база автоматически получает новые поля при первом старте без потери 413 товаров;
- маршрут `/privacy` отдаёт страницу Политики обработки персональных данных;
- CSV-выгрузка заказов содержит сведения о согласии;
- JavaScript прошёл `node --check`, Python-модули — `py_compile`, все 14 Jinja-шаблонов — компиляцию.

Сквозная серверная проверка выполнялась на временной копии `shop.db`: заказ без согласия был отклонён, заказ с согласием создан с зафиксированной версией политики и временем. Тестовые заказы в поставляемую базу не добавлялись.
